# Обновление базы через Alembic

Обновляйте код в прежней папке проекта, сохраняя серверные `.env`, `BOT_TOKEN`, `SUPERADMIN_IDS` и постоянный volume `bot-data`. Серверную базу не нужно заменять базой тестового бота. Схема сверена с [исходной версией проекта](https://github.com/hyfer2867/PleHomework/blob/be0bb8bd1c9935c27a5a2c42d7cad94ad8f3843e/rea_bot/db.py).

## Автоматический запуск

После загрузки нового кода на сервер:

```bash
docker compose stop bot
docker compose up -d --build bot
docker compose logs --tail=100 bot
```

ENTRYPOINT контейнера открывает базу из `DATABASE_PATH`, выполняет Alembic `upgrade head` и только затем запускает основной процесс через `exec`. Если миграция завершается ошибкой, бот не запускается. Повторное поднятие контейнера не применяет уже выполненные ревизии.

Текущая ревизия записывается в таблицу **`alembic_version`** той же базы. Применённые предыдущие ревизии определяются цепочкой `down_revision`; стандартная таблица Alembic хранит текущую вершину этой цепочки, а не отдельный журнал всех запусков.

Старую таблицу `schema_migrations`, если она уже существует, сохраняем как историю прежнего механизма. Новые ревизии учитываются только Alembic. Базы без версии, с прежним механизмом и с промежуточными изменениями структуры принимаются без ручного `stamp`.

## Ревизии

| Ревизия | Изменения |
| --- | --- |
| `0001_initial` | Создаёт отсутствующие таблицы исходного приложения, не заменяя существующие записи |
| `0002_homework_attachments` | Добавляет список `attachments` и переносит старые одиночные вложения |
| `0003_course_materials` | Создаёт материалы курса; добавляет признак удаления у промежуточных версий |

Сохраняются ID, пользователи, роли, привязки к группам, пары, описания ДЗ, даты, авторы, версии, удалённые записи, расписание, история действий и Telegram file IDs. Уже существующие списки вложений, включая пустые, и материалы не перезаписываются. Старые задания не объединяются и не копируются автоматически в материалы курса.

## Резервное копирование и транзакция

Перед обновлением существующей базы создаётся копия через SQLite backup API, включая данные из WAL:

```text
data/backups/bot.sqlite3.pre-0003_course_materials.<время>.<идентификатор>.sqlite3
```

Миграции и изменение `alembic_version` выполняются в одной транзакции с явным `BEGIN IMMEDIATE`, включая DDL в Python 3.12/3.13. Проверяются целостность и внешние ключи. Ошибка резервного копирования или миграции отменяет обновление. На повторном запуске обновлённой базы новая копия не создаётся.

Используйте прежнюю папку/имя Compose-проекта и прежний volume. `docker compose down -v` удаляет данные.

## Применение без запуска бота

На сервере сначала остановите старый процесс. После сборки нового образа:

```bash
docker compose build bot
docker compose run --rm --no-deps --entrypoint python bot -m rea_bot migrate-db --database /app/data/bot.sqlite3
```

Параметр `--entrypoint` позволяет запустить только выбранную команду, без основного ENTRYPOINT. Команда покажет версию и путь к резервной копии. Если файл не существует, она завершится ошибкой, не создавая пустую базу.

Стандартный интерфейс Alembic, без запуска polling:

```bash
docker compose run --rm --no-deps --entrypoint alembic bot current
docker compose run --rm --no-deps --entrypoint alembic bot history
docker compose run --rm --no-deps --entrypoint alembic bot upgrade head
```

Для запуска без Docker установите обновлённые зависимости и выполните:

```bash
python -m pip install -e .
python -m rea_bot migrate-db --database data/bot.sqlite3
# Либо стандартная команда с явным путём:
alembic -x database=data/bot.sqlite3 upgrade head
```

`DATABASE_PATH` из `.env` используется по умолчанию. Параметр `-x database=...` переопределяет путь для Alembic. При обычном запуске `python -m rea_bot` миграции также применяются автоматически.

## Новые миграции

```bash
alembic revision -m "describe the schema change"
```

Заполните `upgrade()` в новом файле `rea_bot/alembic/versions`. Дата и уникальный ID ревизии генерируются Alembic; `down_revision` продолжает цепочку. ORM-моделей для автогенерации сейчас нет, миграции пишутся явно. Проверяйте обновление как пустой, так и заполненной базы. Разрушительные `downgrade` отключены: восстановление выполняется из резервной копии с совместимой версией кода.

## Восстановление

Остановите все процессы, использующие базу. Сохраните отдельно рабочий файл вместе с его `-wal` и `-shm`, если они есть. На месте восстановленной базы не должно остаться прежних `-wal`/`-shm`. Верните файл из `backups` под исходным именем и совместимую версию кода. Не подменяйте открытую базу работающего приложения.

## Токен бота

Для обновления основного бота оставьте его прежний токен: Telegram `file_id` привязаны к боту, получившему файл. Замена токена на токен другого бота не переносит вложения; для этого нужен отдельный экспорт и повторная загрузка файлов.
