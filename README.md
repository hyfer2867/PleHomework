# ДЗ · РЭУ — Telegram-бот

Бот связывает домашние задания с конкретными парами из расписания РЭУ: группа → дата → номер пары → предмет. Управление и просмотр идут в личном чате с ботом, через кнопки на русском языке.

Пилот ограничен **факультетом «Форсайт»**. Расписание и списки загружаются с [rasp.rea.ru](https://rasp.rea.ru/) только по выбору пользователя, без обхода всех факультетов и групп.

## Возможности

| Роль | Просмотр ДЗ | Работа с ДЗ | Управление участниками |
| --- | --- | --- | --- |
| Суперадминистратор | Все подключённые группы | Добавление, изменение, удаление | Назначение/снятие старост, участники и редакторы любой группы |
| Староста | Только своя группа | Добавление, изменение, удаление | Добавление одногруппников, назначение/снятие редакторов, удаление участников |
| Редактор | Только своя группа | Добавление, изменение, удаление | Нет |
| Студент | Только своя группа | Нет | Нет |

- Один студент состоит в одной группе. У группы один староста; редакторов может быть несколько.
- Суперадминистратор сначала назначает старосту. Тот выбирает факультет/курс/уровень/группу и подтверждает привязку. Если назначаемый человек уже состоит в группе, он становится её старостой при отсутствии другого старосты.
- Каждый пользователь сначала нажимает `/start`. После этого его можно добавить по `@username` или числовому ID из `/id`.
- Права привязаны к постоянному Telegram ID. `@username` используется для поиска и может изменяться. Перед назначением бот показывает имя и ID для проверки. Если пользователь не обращался к боту более суток, поиск по username требует повторного `/start`; поиск по ID продолжает работать.
- ДЗ — текст до 3000 символов, одна фотография или документ с подписью. К паре можно добавить несколько отдельных заданий. Альбомы не поддерживаются.
- Просмотр: **Сегодня / Завтра / Расписание и ДЗ / Только ДЗ**, переключение недель, страницы по восемь пар.
- Кнопки обновляют то сообщение, на котором нажаты. **⬅️ Назад** возвращает на предыдущий экран, сохраняя выбранную неделю, фильтр и страницу. **🏠 Главное меню** начинает выбор заново.
- ДЗ одной пары перелистываются в одной карточке кнопками **← ДЗ / ДЗ →**. Предпросмотр после ввода и результат сохранения/удаления показываются в этом же сообщении. Фото и документы при открытии приходят отдельно.
- Если сообщение меню удалено или Telegram запретил его редактирование, бот создаёт новое меню. История экранов хранится в SQLite и переживает перезапуск.
- Предпросмотр перед сохранением, подтверждение изменения прав и удаления. Отмена аннулирует незавершённые предпросмотры ДЗ и назначения людей.
- Защита от повторного сохранения одним и тем же подтверждением и от потери чужих изменений при одновременном редактировании.

## Быстрый запуск на компьютере

Понадобится Python 3.12 или новее. Выполняйте команды в папке проекта.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
cp .env.example .env
```

В Windows активация окружения: `.venv\Scripts\activate`; `.env.example` можно скопировать в `.env` через проводник.

1. Откройте официальный [@BotFather](https://t.me/BotFather) в Telegram, отправьте `/newbot`, задайте имя и username бота.
2. Впишите выданный токен в локальный файл `.env`, в `BOT_TOKEN`. Токен остаётся у вас; отправлять его в чат не требуется.
3. Если ваш числовой Telegram ID известен, заполните `SUPERADMIN_IDS`. Если нет, оставьте это поле пустым, запустите бота и отправьте ему `/id`:

   ```bash
   python -m rea_bot
   ```

4. Остановите бота (`Ctrl+C`), впишите полученный ID в `SUPERADMIN_IDS` и запустите снова. Без этого параметра административные права не выдаются никому.
5. Откройте `/start` — появится меню суперадминистратора.

Пример `.env`:

```dotenv
BOT_TOKEN=ваш_токен_из_BotFather
SUPERADMIN_IDS=ваш_числовой_Telegram_ID
DATABASE_PATH=data/bot.sqlite3
TIMEZONE=Europe/Moscow
```

Бот работает, пока процесс запущен и компьютер подключён к интернету. Для круглосуточной работы запускайте на постоянно доступном сервере. Используется long polling; домен и входящие HTTP-порты не нужны. У одного токена должен работать один экземпляр приложения, без активного webhook от другого сервиса.

## Обновление уже запущенного бота

Если вы запускаете этот проект из той же папки с `pip install -e .`, остановите процесс через `Ctrl+C` и снова выполните `python -m rea_bot`. Затем отправьте `/start` в Telegram. Переустановка зависимостей для обновления навигации не требуется. Настройки `.env`, участники и ДЗ сохраняются; новая таблица истории экранов создаётся автоматически при старте.

Для Docker: `docker compose up -d --build`.

## Первое подключение группы

1. Будущий староста открывает бота и нажимает `/start`.
2. Суперадминистратор выбирает **Назначить старосту**, отправляет `@username` или ID, проверяет пользователя и подтверждает.
3. Староста открывает `/start` → **Выбрать группу · Форсайт** → курс → уровень обучения → группа → **Да, моя группа**.
4. Одногруппники нажимают `/start`. Староста открывает **Моя группа → Участники и права → Добавить**, вводит их usernames/ID и подтверждает каждого.
5. Для помощника: **Участники и права → Выдать права ДЗ**. Помощник уже должен состоять в группе.
6. Для задания: **Расписание и ДЗ → нужная пара → Добавить ДЗ → сообщение/файл → Сохранить ДЗ**.

Для замены старосты суперадминистратор сначала снимает полномочия старого — тот остаётся студентом своей группы — затем назначает нового. Для переноса студента между группами сначала удалите старую привязку через управление соответствующей группой, затем добавьте в новую.

## Docker / сервер

После заполнения `.env`:

```bash
docker compose up -d --build
docker compose logs -f bot
```

SQLite хранится в постоянном Docker volume `bot-data`, контейнер запускается от отдельного пользователя. Обновление образа не удаляет базу. `docker compose down` сохраняет volume; вариант с `-v` удаляет его вместе с данными.

Для резервной копии локальной базы используйте SQLite backup API, в том числе при работающем боте:

```bash
python - <<'PY'
import sqlite3
with sqlite3.connect('data/bot.sqlite3') as source:
    with sqlite3.connect('backup.sqlite3') as target:
        source.backup(target)
PY
```

В Docker ту же операцию можно выполнить через `docker compose exec bot python` для пути `/app/data/bot.sqlite3`, после чего забрать файл командой `docker compose cp`. База содержит пользователей, группы, задания, историю изменений и Telegram file IDs. `.env` и рабочая база исключены из Git и Docker build context.

## Как загружается расписание

Адаптер повторяет публичную последовательность сайта:

1. Открывает главную страницу и сохраняет cookie сессии — запросы к служебным адресам без неё могут получать HTTP 403.
2. `POST /Schedule/Navigator`: выбранный факультет → курс → уровень → группы. Формат — multipart, как `FormData` в скрипте сайта.
3. `GET /Schedule/ScheduleCard`: только одна группа и одна неделя.

По умолчанию:

- между запросами минимум **3 секунды**, запросы выполняются последовательно;
- списки кэшируются **24 часа**, расписание **30 минут**; кэш переживает перезапуск;
- одинаковые одновременные открытия не создают несколько загрузок;
- при ошибке сайта действует минутная пауза перед следующей попыткой;
- сохранённая копия показывается с пометкой об устаревании и временем загрузки;
- кнопка «Обновить» также соблюдает TTL, а не обходит ограничение запросов.

На холодном запуске выбор группы и первой недели требует до пяти запросов. Другие курсы и группы не загружаются заранее. Параметры интервала, TTL и разрешённого факультета находятся в `.env.example`.

Ключ пары включает дату, номер, предмет, вид занятия и идентификатор занятия сайта. Изменение аудитории не отвязывает ДЗ. Если пара исчезла или изменила идентичность, её ДЗ остаётся видимым с предупреждением. Автоматически переносить его на другую дату бот не будет: староста проверяет новую пару и при необходимости переносит задание вручную. Это исключает незаметное прикрепление задания к неверной паре.

Проверяется соответствие дат запрошенной неделе и наличие полной разметки понедельника–субботы. Страница входа, ошибка или неполная таблица не очищают сохранённые пары. Нумерация учебных недель рассчитывается от недели, содержащей 1 сентября; ответ сайта дополнительно проверяется по датам.

## Проверка без Telegram-токена

Тесты не отправляют сообщений в Telegram и не обращаются к сайту:

```bash
pip install -e '.[dev]'
pytest -q
ruff check .
```

Отдельная ручная проверка сети — **только выбранная группа**, до пяти запросов с паузами:

```bash
python -m rea_bot check-schedule \
  --course '1-й курс' \
  --level 'Бакалавр' \
  --group '15.22Д-ПМ01/26б'
```

Без `--group` команда покажет список групп выбранного курса/уровня и не загрузит их расписания. `--monday YYYY-MM-DD` позволяет выбрать конкретную неделю.

Сохранённый HTML можно проверить вообще без сети:

```bash
python -m rea_bot parse-schedule tests/fixtures/schedule.html
```

8 ноября 2026 года сохранены все оставшиеся недели до 31 декабря для двух подключённых групп «Форсайта»: `15.22Д-ПМ01/26б` (120 будущих пар) и `15.22Д-Э01/26б` (107 будущих пар). Выполнены 16 последовательных запросов недель и одно открытие главной страницы для сессии, с интервалом 8 секунд.

Откройте группу → «🗓 Выбрать неделю». Список показывает все сохранённые недели, включая декабрь; доступно переключение страниц. Просмотр декабрьской недели проверен в Telegram. На неделю с 28 декабря у ПМ сайт не указал занятий, у Э вернул 4 пары. Пустое расписание может быть дополнено университетом.

Публичные расписания включены в `rea_bot/data/schedule-2026.json` и восстанавливаются при запуске с настроенным владельцем. Файл не содержит пользователей, токена и ДЗ. Более новые данные в базе сохраняются. Рабочая SQLite-база с существующими участниками и заданиями остаётся на месте.

Чтобы сократить количество запросов, недели дальше ближайших семи дней используют кэш до 24 часов. Ближайшие недели — прежний интервал из настроек (по умолчанию 30 минут). Дата последней загрузки показана в карточке недели.

Навигация: группа → «Расписание и ДЗ» → неделя → день недели с датой → пара. На экране недели доступна кнопка «Все ДЗ за неделю»: список заданий по датам с кратким текстом и переходом к полному ДЗ/вложению. Длинный список перелистывается, возврат сохраняет выбранный день.

## Предварительное добавление по usernames

«Участники и права» → «Добавить»: отправьте до 100 @username через пробел, запятую или с новой строки. Бот покажет подтверждение. Зарегистрированные пользователи добавляются сразу, неизвестные ожидают первого `/start`. При входе привязка закрепляется за числовым Telegram ID с ролью студента. Записи действуют 30 дней; список и отмена доступны в «Ожидают входа». При снятии полномочий у создателя записи она перестаёт выдавать доступ. Существующие участники других групп автоматически не переносятся. Назначение старост и редакторов по-прежнему требует зарегистрированного пользователя.

Перед первым входом username может измениться или перейти другому аккаунту — проверяйте список ожидающих и отменяйте неактуальные записи. Изменение username после вступления не передаёт права другому аккаунту.

Удаление участников: «Участники и права» → «Удалить из группы» → выбор человека → подтверждение. Выбор использует сохранённый Telegram ID, не требует повторного /start и работает без username.

Владелец может удалить старосту через общий список участников. Подтверждение снимает полномочия и отменяет созданные старостой ожидающие приглашения; остальные участники и ДЗ сохраняются.

Снятие полномочий: «Старосты» → «Снять полномочия» → выбор человека из списка → подтверждение. Повторный /start не нужен. Человек остаётся студентом своей группы.

Все действия с правами (назначение/снятие старосты, выдача/снятие прав редактора) и удаление участников используют списки с подтверждением. Пустые списки сопровождаются заметным информационным сообщением. Для предварительного добавления по usernames сохранён ввод списком.

На Mac можно запускать бота двойным щелчком по «Запустить бота.command». Скрипт использует существующий .env. Настройки читаются явно из папки проекта, а относительный путь к базе вычисляется от папки настроек независимо от текущего каталога терминала. Файл .env.example повторно копировать поверх .env не требуется.

## Политика запросов (актуальная)

Просмотр недель, дней, пар, ДЗ и кнопка «Показать сохранённое» работают полностью из базы и не вызывают запросов расписания — для всех ролей. Если неделя ещё не сохранена, бот сообщает об этом.

Текущая и следующая календарные недели проверяются один раз в день после 07:00 Europe/Moscow (`SCHEDULE_REFRESH_HOUR`). Если бот был выключен утром, проверка выполняется после запуска. Попытки фиксируются в SQLite до запроса и не повторяются в тот же день при перезапуске; при ошибке данные сохраняются. Проверяются только подключённые группы разрешённого факультета. Для двух групп — четыре запроса недель за день плюс открытие главной страницы для сессии при необходимости. Для выполнения по расписанию процесс должен работать.

Только владелец видит кнопку «Загрузить до конца года» в главном меню. Она показывает число групп и запросов и требует подтверждения. После подтверждения последовательно обновляет недели всех подключённых групп от текущей недели до 31 декабря. Прогресс отображается в одном сообщении. Повторное нажатие того же подтверждения не запускает загрузку заново. При ошибке загрузка останавливается, уже сохранённые недели остаются. ДЗ и участники сохраняются.

Каталог факультета/курсов/групп по-прежнему загружается отдельно при подключении новой группы с кэшированием. Диагностическая CLI-команда `check-schedule` — явная ручная сетевая проверка, не пользовательский просмотр.

Эта политика заменяет описанное выше обновление расписания по TTL при открытии. TTL используется только сетевыми служебными операциями; пользовательская навигация к сайту расписаний не обращается.

В меню группы оставлена одна кнопка «Расписание и ДЗ» для выбора недели. На экранах дней («Сегодня», «Завтра», выбранный день) кнопки «← День» / «День →» переключают соседние даты, включая переход через границы недель; «Вся неделя» открывает дни соответствующей недели. Просмотр остаётся полностью локальным.

## Вложения прямо в навигации

Карточка ДЗ с вложением — сообщение с документом, подписью задания и кнопками навигации. «Открыть вложение» больше не требуется. Фото, присланные как Telegram-фото, при первом показе скачиваются в полученном от Telegram качестве и загружаются как `homework-photo.jpg`; полученный document file ID сохраняется в отдельном кэше для повторного использования. Фото, изначально присланное как файл, остаётся исходным файлом. Исходное качество до сжатия Telegram таким преобразованием не восстанавливается.

Длинный текст подписей перелистывается кнопками «← Текст» / «Текст →» с учётом лимита Telegram. Файл, текст и кнопки находятся в одном сообщении. При смене вложений редактируется текущая карточка. При возврате к текстовому меню создаётся текстовая карточка и удаляется прежняя медиа-карточка, поскольку Telegram не позволяет убрать медиа через editMessageText. Если удаление недоступно, старая клавиатура снимается. Превью вложения также показывается до сохранения, без публикации задания.

На работающем боте проверены отображение существующего документа в навигации и возврат к обычному меню. Тестами дополнительно проверены JPG-конвертация без изменения байтов, повторное использование Telegram file ID, длинные подписи и отсутствие доступа к чужим вложениям.

## Текст и вложение как одно задание

При добавлении ДЗ можно прислать файл/фото с подписью одним сообщением или сначала текст, затем вложение (либо наоборот). Пока не нажата кнопка «Сохранить ДЗ», новые сообщения дополняют тот же черновик: текст добавляется абзацами, новое вложение заменяет предыдущее. Общее ограничение текста — 3000 символов, одно вложение на задание. Старые кнопки сохранения предыдущих версий черновика аннулируются.

У текстового задания есть кнопка «Прикрепить файл»: она сохраняет описание и добавляет вложение в то же ДЗ без создания второй записи. Редактирование существующего задания сохраняет прежнее вложение, если новое не отправлено; первый новый текст при обычном редактировании заменяет старый. Текст ДЗ и предпросмотра визуально выделен блоком цитаты. Существующие отдельные задания не объединяются автоматически.

В карточке с вложением кнопка «Прислать вложенный файл» отправляет отдельную копию документа/JPG без изменения навигации. Права повторно проверяются при нажатии. Технические номера ДЗ вида #6 видны только владельцу: скрыты для студентов, редакторов и старост в карточках, недельных списках и подтверждениях удаления.

Экран дня содержит только группу, дату, легенду значков и кнопки пар. Описания пар в тексте не дублируются. Для всех ДЗ одной пары используется общий заголовок с предметом, временем, типом занятия и аудиторией, в том числе для файловых карточек; длина текста подстраивается под лимит подписи Telegram.

/info и /help для студентов содержат только краткую инструкцию поиска ДЗ и навигации без описания назначения ролей.
